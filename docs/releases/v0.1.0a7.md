# Agnara v0.1.0a7 — Publication and Security Recovery

> Draft release notes. Do not tag or publish while
> [`publication.json`](publication.json) is `UNVERIFIED`.

## What this release is

`0.1.0a7` is the recovery after the immutable `v0.1.0a6` workflow failed on
its first PyPI upload. It carries the A6 runtime unchanged, fixes three
release-blocking static-analysis findings, and strengthens the human
publication evidence. Execution Semantics is not included; its complete scope
moves intact to `0.1.0a8`.

## Why A6 failed

PyPI rejected the first distribution, whose metadata declares
`Name: agnara-a2a`, with `400 Non-user identities cannot create new projects`.
The artifact filename `agnara_a2a-0.1.0a6-...` is correct normalization and is
not the project name. No pending publisher matched canonical project
`agnara-a2a` and the GitHub OIDC identity. No A6 file was uploaded.

## Exact PyPI configuration

Each active or Pending Trusted Publisher must use provider **GitHub Actions**,
owner `Blandskron`, repository `agnara`, workflow `release.yml`, and
environment `pypi`. Its Project name must be exactly the corresponding value:

- `agnara`
- `agnara-a2a`
- `agnara-cli`
- `agnara-events`
- `agnara-http`
- `agnara-mcp`
- `agnara-telemetry`

Delete any mismatched `agnara-a2a` pending entry and recreate it rather than
renaming the Python distribution. Read all six unreached pending entries back
too; A6 provided no evidence that PyPI would accept them.

## Owner checklist before tagging

1. Correct `agnara-a2a` and read back all seven project names and tuples.
2. Record fresh confirmation for target `0.1.0a7` in `publication.json`.
3. Run publication readiness offline and online; both must pass.
4. Create the tag only after the recovery PR is merged to `main` and every
   required release gate is satisfied.
