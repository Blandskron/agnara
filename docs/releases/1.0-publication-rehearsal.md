# V1-44: 1.0 publication rehearsal and immutable artifact verification

## Scope

This is a no-upload rehearsal of the protected release path. It began from
`develop` commit `4231617fa3039e5a3d8b0826445204d97f4f01bd` and made the
release-only version transition in a disposable detached worktree. The tracked
candidate remained `1.0.0.dev0`; the temporary worktree used the repository
version tool to make the seven package metadata files and lockfile exactly
`1.0.0`, then ran its check mode before building. No tag, GitHub Release, PyPI
or TestPyPI upload, `main` merge, credential use, or environment approval
occurred.

The reviewed publication set is unchanged: `agnara`, `agnara-a2a`,
`agnara-cli`, `agnara-events`, `agnara-http`, `agnara-mcp`, and
`agnara-telemetry`. The kernel remains last in the governed publication order.

## Installed-artifact clean room

A fresh CPython 3.14.4 environment received the adapter-owned third-party
requirements from the index. It then installed all seven candidate wheels with
`--no-index --find-links dist`. `check_distributions.py --require-installed
--expected-version 1.0.0`, imports of all seven package names, and
`agnara --version` passed. The console command reported `agnara 1.0.0`.

The locked runtime export was audited with `pip-audit 2.10.1 --strict`; it
reported no known vulnerabilities. This is a point-in-time dependency-database
result, not an attestation or a publication authorization.

## Protected workflow and deliberate refusals

The release workflow remains `workflow_dispatch`-only from `main`, with the
tag as a post-publication consequence. A read-only check found no `v1.0.0`
tag. The GitHub `pypi` environment has a required reviewer and a custom branch
policy. No credential was read or used.

Local `check_release_preconditions.py` correctly refused: it was not running
as a dispatched GitHub Action from `refs/heads/main`, had no dispatched SHA,
repository context, or workflow token. That refusal is evidence that a shell
session cannot bypass the protected path.

`check_publication_readiness.py --version 1.0.0 --phase final --dist dist`
correctly refused because the final cut has not yet created all three final
release artifacts: `docs/releases/v1.0.0.md`, a dated `CHANGELOG.md`
`[1.0.0]` section, and its comparison link. Those documents must be created
from the accepted final release branch; this rehearsal does not fabricate them.

PEP 740 attestations, public-index completeness and the final tag/GitHub
Release remain `NEEDS CI` and protected maintainer actions. This evidence is
fresh only for the SHA and temporary artifact hashes above; any release-code,
metadata, lockfile or version change requires a new rehearsal.
