# Agnara v1.0.0 — First Stable Release

`1.0.0` is Agnara's first stable release and the start of the `1.x`
compatibility line. It stabilizes the capability runtime and its documented
public surface across the seven synchronized distributions. Upgrading from the
`0.1.0a8` publication baseline needs source changes; follow the
[A8-to-1.0 migration guide](../MIGRATION_A8_TO_1_0.md).

Requires CPython `>=3.14`. Licensed under Apache License 2.0.

## Distributions

All seven distributions carry exactly `1.0.0`, and each adapter pins
`agnara==1.0.0`. Install matching versions only.

| Distribution | Import | Role |
| --- | --- | --- |
| `agnara` | `agnara` | Transport-neutral kernel, standard library only |
| `agnara-http` | `agnara_http` | HTTP/ASGI and SSE projection |
| `agnara-mcp` | `agnara_mcp` | MCP projection |
| `agnara-cli` | `agnara_cli` | `agnara` console command |
| `agnara-telemetry` | `agnara_telemetry` | OpenTelemetry bridge |
| `agnara-a2a` | `agnara_a2a` | Reserved namespace, no exports |
| `agnara-events` | `agnara_events` | Reserved namespace, no exports |

```bash
pip install "agnara==1.0.0" "agnara-http==1.0.0"
```

## Stable public API

- **166 stable exports across 13 modules**, one canonical import path per
  name. The exact inventory is `docs/public-api.json`, and the policy is
  `docs/PUBLIC_API.md`.
- 171 duplicate leaf-module re-exports are no longer public API. Import from
  the canonical module only.
- Within `1.x`, a stable name, its import path, its signature and its
  documented behaviour remain compatible. A deprecated name cannot be removed
  before `2.0`.

## What 1.0 contains

- **Execution semantics.** Complete-result invocation and a streaming kernel
  contract (`streaming=True`, `open_stream`, `StreamTerminal`,
  `StreamInterrupted`) with pull-based backpressure. The runtime generates the
  execution identity. Operational idempotency is opt-in and applies only to
  complete direct invocation (`IdempotencyInvocation`). Nested composition
  runs through `CapabilityInvoker` on the same frozen snapshot, with policy,
  deadlines, cancellation and depth limits.
- **Authority boundary.** `ExecutionContext.principal` must be a `Principal`.
  `principal`, `confirmation_evidence` and `idempotency` cannot be reassigned
  during an execution, which closes a nested-composition
  authority-amplification path.
- **HTTP.** 14 stable `agnara_http` exports and `Http.sse` for server-sent
  events. Request methods are matched exactly as RFC 9110 requires, and an
  unroutable method is answered as unmatched.
- **Interoperability.** Agnara runs standalone, as a host, embedded in a host
  application and side by side with one, and the kernel does not couple to a
  framework. Version-pinned fixtures cover Starlette 1.6.0, FastAPI 0.141.1,
  Django 6.1.1, Litestar 2.24.0, SQLAlchemy 2.0.54 (SQLite) and the
  OpenTelemetry SDK 1.44.0. These are tested fixtures, not claims of broad
  framework, ORM or exporter support.
- **Performance.** 15 calibrated budgets, stated as ratios between scenarios in
  the same run, fail CI on regression.

## Breaking changes from 0.1.0a8

- Import DI from `agnara.di`, not `agnara.core.di`.
- The introspection snapshot field `apps` is now `applications`, both in
  `IntrospectionSnapshot.applications` and in the serialized document.
- Leaf-module aliases are gone. Use the paths in `docs/public-api.json`.
- A principal-like object that is not a `Principal` is refused, and the
  verified authority fields cannot be reassigned.
- HTTP method matching is case-sensitive: `post` no longer reaches a `POST`
  route.

Run `python scripts/check_public_imports.py path/to/application` after
migrating.

## Security

- Remediates
  [GHSA-j5rx-vm8v-f7p3](https://github.com/advisories/GHSA-j5rx-vm8v-f7p3)
  (CWE-532). In versions `<= 0.1.0a8`, the default runtime logs could contain
  unexpected capability exception text and tracebacks. The planned `0.1.0a9`
  hotfix was never published, so `1.0.0` is the first release with the fix.
- The threat model is `docs/THREAT_MODEL.md`. Report vulnerabilities as
  described in `SECURITY.md`.

## Verifying this release

The release workflow publishes through PyPI Trusted Publishing, with a
separate OIDC identity for each project. Uploads carry PEP 740 attestations
produced under that workflow identity. Agnara holds no signing key. The GitHub
Release attaches the same seven wheels and seven sdists. The release run keeps
their `SHA256SUMS` manifest and a CycloneDX 1.6 SBOM as run artifacts, and
every job that touches the bundle checks it against that manifest. The
reference container image is published as `ghcr.io/blandskron/agnara:1.0.0`
and `docker.io/blandskron/agnara:1.0.0`, with a build SBOM and provenance. See
`SECURITY.md` for the readback procedure.

## Not in 1.0

The following are outside the `1.0` contract: delegation (RFC 0005 is a
draft), WebSocket, SSE replay, MCP streaming, streamed request bodies, durable
idempotency storage, retry, workers, schedulers, brokers and workflow engines.
Python 3.15 readiness is a post-1.0 program; see `ROADMAP.md`.

Full change record: `CHANGELOG.md`, section `[1.0.0]`.
