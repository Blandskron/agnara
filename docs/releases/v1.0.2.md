# Agnara v1.0.2 — Security and Publication Recovery

`1.0.2` is the complete synchronized patch for Agnara's seven distributions.
It carries four security fixes made after `1.0.0` and repairs the phased
publication candidate lookup. It preserves the documented 1.x public API.
Applications using `1.0.0` should upgrade every installed Agnara distribution
to `1.0.2` together. Requires CPython `>=3.14`; Apache License 2.0.

```bash
pip install --upgrade "agnara==1.0.2" "agnara-http==1.0.2"
```

Install any other Agnara adapter at `1.0.2` as well. The set is `agnara`,
`agnara-a2a`, `agnara-cli`, `agnara-events`, `agnara-http`, `agnara-mcp` and
`agnara-telemetry`; every adapter pins `agnara==1.0.2`.

## Security fixes

- Directly constructed execution plans enforce declared scope, application
  and confirmation policies, closing direct and MCP authorization bypasses.
- Caller-facing authorization denials omit missing scope labels; operators
  may opt in to diagnostics.
- Viewer-specific Explorer and discovery responses are private or no-store
  across the whole response, preventing shared-cache replay.
- GET-only publication routes match HTTP method case exactly, refusing
  lowercase or malformed methods.

The logging issue in
[GHSA-j5rx-vm8v-f7p3](https://github.com/Blandskron/agnara/security/advisories/GHSA-j5rx-vm8v-f7p3)
was fixed in `1.0.0` and is not a new `1.0.2` fix.

## Publication recovery

The `1.0.1` bootstrap-1 run published `agnara-a2a`, `agnara-cli` and
`agnara-events`, but the next phase rejected its valid candidate because the
GitHub Actions API returned a bare workflow path. The remaining four
distributions were not uploaded, and no `v1.0.1` tag or GitHub Release was
created. Do not install or recommend that incomplete version.

The candidate checker now accepts GitHub's bare workflow path while still
requiring a successful dispatch from `main` and the exact same commit in every
phase. The selected `1.0.2` version is used throughout the workflow. The
protected release process will publish and verify all seven distributions
before it creates the immutable `v1.0.2` tag and GitHub Release; preparation
of this note does not assert those steps have happened.

Full change record: `CHANGELOG.md`, section `[1.0.2]`.
