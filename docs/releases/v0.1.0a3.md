# Agnara v0.1.0a3 — Integration Alpha

## What this alpha demonstrates

This experimental alpha extends the installable capability kernel from
`v0.1.0a2` with protocol-neutral introspection, explicit discovery filtering
and stronger telemetry contracts. Within the repository, HTTP discovery,
Explorer, CLI and MCP consume the same compiled capability model.

This is evidence of subsystem integration, not external application validation
or production readiness. The public API may change without a deprecation cycle.

## Highlights

- **Introspection and visibility:** immutable, versioned snapshots describe
  capabilities, schemas, dependencies, policies and adapter exposures. Explicit
  visibility decisions filter capabilities and fields before serialization.
- **Discovery and Explorer:** an authorized HTTP discovery endpoint and
  read-only HTML Explorer share that filtered snapshot. Explorer supports
  application, capability, schema and dependency views, with security headers,
  private error responses and browser checks for navigation and accessibility.
- **MCP invocation:** `McpToolInvoker` and `build_mcp_server` dispatch tool calls,
  apply scope policy before effects, map canonical outcomes and propagate
  cancellation. Bounded official-SDK conformance tests cover the implemented
  surface; see [the coverage matrix](https://github.com/Blandskron/agnara/blob/v0.1.0a3/docs/MCP_CONFORMANCE.md).
- **CLI and scaffolding:** `inspect`, `graph`, `context` and `schema openapi`
  consume existing projections. `agnara.toml` and `agnara apps` describe bounded
  contexts. `project create` and `app create` support deterministic plans,
  `--dry-run`, JSON output and conflict refusal, with a modular-hexagonal app
  template. Generated apps require explicit wiring into `bootstrap.py`.
- **Telemetry:** invocation identity pairs lifecycle events. Hook configuration
  is validated at startup, transport-supplied tracking IDs reach events and
  plans without observers skip event construction. Repository-only
  OpenTelemetry hooks provide application-owned metrics and capability spans;
  failure/timeout spans include the stable outcome as `error.type`.
- **Release preparation:** the existing readiness checker also validates a
  cut, dated target changelog, synchronized versions and comparison links.

## Install

After publication:

```bash
python -m pip install agnara==0.1.0a3
```

Requires CPython 3.14 or newer. `agnara` has no third-party dependencies.
Only **`agnara`** is published to PyPI by the existing Trusted Publishing
workflow. The six sibling distributions share version `0.1.0a3` and are
buildable from this repository, but are not uploaded to PyPI.

The [quick start](https://github.com/Blandskron/agnara/blob/v0.1.0a3/examples/quickstart.py) demonstrates dependency
injection, compiled input validation and canonical invocation results using
the installed core.

## Migration from v0.1.0a2

`InvocationStartEvent` and `InvocationTerminalEvent` now require
`invocation_id`. Code constructing these values must supply a matching identity
for a start/terminal pair; prefer keyword construction. A caller-provided,
repeatable `tracking_id` is not an invocation identity. Hooks that only read
events need no constructor change.

Plans reject missing, non-callable, coroutine or generator telemetry callbacks
at startup. Provide synchronous callbacks accepting one event and returning
`None`; callbacks must not block.

## Validation

The release PR records the exact source and release commits, commands, results,
built artifacts and required CI. Release preparation validates all seven
distributions, the lockfile, lint, formatting, types, full tests (including
architecture, HTTP, MCP and CLI), dedicated browser checks and clean installed
artifacts outside the checkout. Publication remains a separate operation and
re-runs the existing CI and artifact gates before OIDC upload.

Local preparation on CPython 3.14.4 / Windows passed lint, formatting and
types; **2059 tests passed**, with the 31 browser-only cases subsequently
run separately and **all 31 passing**. All seven wheels and sdists built with
`0.1.0a3`, Python `>=3.14` and Apache-2.0 metadata. The installed core executed
the quick start outside the checkout; all seven installed packages imported
from `site-packages`, and the installed CLI version/help smoke tests passed.
PR CI remains authoritative for the complete supported OS matrix.

No new comparative performance claim is made. The recorded MCP and telemetry
baselines describe their measurement boundaries and workstation limitations.

## Known limitations

- This remains **experimental alpha**, as confirmed by the maintainer on
  2026-09-06. No production-readiness or general security guarantee is made.
- Threat modeling, a dependency audit, secret scanning and dedicated security
  static analysis remain pending. Private vulnerability reporting is enabled
  at [GitHub Security Advisories](https://github.com/Blandskron/agnara/security/advisories/new).
  Existing policy, redaction and browser tests provide bounded evidence only.
- MCP evidence uses the pinned SDK and in-process exchanges; it does not prove
  network transport or complete protocol conformance. Task-augmented and resumed
  tool calls are unsupported. Application verification remains necessary for
  confirmation evidence.
- Explorer is read-only. CLI exposure selection, profiles, shortcut aliases
  and the minimal app template are not implemented. A2A and events are
  placeholders, and distributed tasks are not implemented.
- Applications own identity verification, telemetry providers/exporters and
  their lifecycle. There is no new free-threading or scalability claim.
