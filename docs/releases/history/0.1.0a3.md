This is the first maturity snapshot. `0.1.0a1` and `0.1.0a2` predate the
readiness program and their release notes remain the record for them.

## What this release proved

That the major subsystems are one system rather than a collection of parts
sharing a repository. HTTP discovery, the Explorer, the CLI and MCP consume the
same compiled capability model, and the introspection snapshot they read is
produced once by the kernel rather than derived independently by each surface.

Concretely: immutable versioned introspection snapshots with per-field
visibility decisions; an authorized HTTP discovery endpoint and read-only
Explorer sharing that filtered snapshot; MCP tool dispatch applying scope
policy before effects and mapping canonical outcomes; CLI `inspect`, `graph`,
`context` and `schema openapi` consuming existing projections rather than
re-deriving them; and paired invocation identity across telemetry lifecycle
events.

## What it did not prove

That anyone outside this repository can use Agnara. No application external to
the workspace consumed the framework during this release. Every HTTP
integration was exercised through the adapter's private modules, because
`agnara-http` declares no public composition surface.

Only `agnara` was uploaded to PyPI. The six sibling distributions were built
and version-synchronized but not published, so a external consumer could not
install an adapter as an ordinary dependency.

No production readiness, general security posture, complete protocol
conformance or new performance claim was made.

## Architectural state at this point

- The kernel is standard-library only and is the sole published distribution.
- Registration closes at `compile()`; the compiled model is frozen and holds no
  runtime objects reachable from a snapshot.
- Capability identity is `<namespace>.<name>`, the namespace being the owning
  app.
- Ten canonical failure codes are transport-neutral, and deadlines map to
  `TIMEOUT`. Cancellation propagates and is never translated.
- Idempotency is declared metadata; the runtime performs no deduplication.
- `agnara-http` is `EXPERIMENTAL` with an empty public surface; `agnara-mcp`,
  `agnara-cli` and `agnara-telemetry` declare public surfaces; `agnara-a2a` and
  `agnara-events` are reserved namespaces with no implementation.
- The public API manifest governs the 41 top-level `agnara` exports. Public
  subpackage surfaces are not yet governed.

## Known limitations carried forward

These were accepted for this release and remain open work, not defects:

- Six of seven distributions are unpublished, so external cross-transport
  applications cannot install adapters normally.
- `agnara-http` has no public composition API, so composing HTTP requires
  private imports.
- Threat modeling, dependency audit, secret scanning, SBOM and signing are not
  configured.
- Benchmarks are baselines only: no budgets and no regression gate.
- MCP conformance is repository-authored and bounded; no upstream suite runs.

## What comes next

`0.1.0a4` — Application Alpha — asks whether Agnara can be consumed as a
framework rather than exercised internally. Its evidence must come from
applications outside this repository, and the two limitations above are the
ones most likely to shape it.
