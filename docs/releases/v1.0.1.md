# Agnara v1.0.1 — Security Patch

`1.0.1` updates the seven synchronized Agnara distributions with security
fixes merged after `v1.0.0`. It preserves the documented `1.x` public API.
Applications using `1.0.0` should upgrade every installed Agnara distribution
to the same version.

Requires CPython `>=3.14`. Licensed under Apache License 2.0.

```bash
pip install --upgrade "agnara==1.0.1" "agnara-http==1.0.1"
```

Install any other Agnara adapter at `1.0.1` as well. The seven distributions
are `agnara`, `agnara-a2a`, `agnara-cli`, `agnara-events`, `agnara-http`,
`agnara-mcp` and `agnara-telemetry`; every adapter pins `agnara==1.0.1`.

## Security fixes

- Directly constructed execution plans now enforce declared scope,
  application and confirmation policies. This closes a path for direct and MCP
  invocations to bypass capability authorization.
- Authorization denials no longer disclose missing scope labels to callers.
  Operators can still opt in to diagnostics.
- Viewer-specific Explorer and discovery responses require a private or
  no-store directive for the entire response, preventing shared caches from
  replaying filtered metadata across viewers.
- Publication routes match HTTP method case exactly. Lowercase or malformed
  methods cannot reach GET-only schema, documentation, discovery or Explorer
  content.

## Release integrity

Phased publication is pinned to the candidate commit selected by the first
successful phase. Later phases compare published PyPI file SHA-256 values with
the retained build before uploading more distributions.

The logging issue in
[GHSA-j5rx-vm8v-f7p3](https://github.com/Blandskron/agnara/security/advisories/GHSA-j5rx-vm8v-f7p3)
was already fixed in `1.0.0`. It is not a new `1.0.1` fix.

The protected release workflow publishes all seven distributions, verifies
their index artifacts and then creates the immutable `v1.0.1` tag and GitHub
Release. The run also records the artifact digests and SBOM. See `SECURITY.md`
for the readback procedure.
