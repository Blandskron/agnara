# Agnara v0.1.0a6 — Aborted Publication Recovery

> **Publication status: aborted on the first upload.** PyPI rejected
> `agnara-a2a` with `400 Non-user identities cannot create new projects`.
> No A6 artifact was published; the tag remains immutable.

## What this release is

`0.1.0a6` is the next publication-recovery attempt after the immutable
`v0.1.0a5` workflow stopped safely before its first upload. It changes no
runtime behavior and carries the same framework implementation with synchronized
package metadata for all seven distributions.

The release kept the sequenced upload, kernel-last ordering, post-publication
verification and sanitized diagnostics introduced for A5. Execution Semantics
was not part of this release and moves intact to `0.1.0a8` through ADR 0081.

## PyPI state before release

- `agnara` exists with `0.1.0a2`, `0.1.0a3` and the partial `0.1.0a4` release.
- No `0.1.0a5` artifact exists.
- `agnara-a2a`, `agnara-cli`, `agnara-events`, `agnara-http`, `agnara-mcp` and
  `agnara-telemetry` do not yet exist publicly.

## Historical outcome

The owner confirmation recorded before the tag was insufficient: the actual
PyPI upload proved that no pending publisher matched canonical Project name
`agnara-a2a` and the OIDC identity. Recovery continues in `0.1.0a7`; A6 must
not be rerun, moved or reused.
