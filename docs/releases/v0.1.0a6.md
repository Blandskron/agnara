# Agnara v0.1.0a6 — Publication Recovery

> Draft release notes. Do not tag or publish while
> [`publication.json`](publication.json) is `UNVERIFIED`.

## What this release is

`0.1.0a6` is the next publication-recovery attempt after the immutable
`v0.1.0a5` workflow stopped safely before its first upload. It changes no
runtime behavior and carries the same framework implementation with synchronized
package metadata for all seven distributions.

The release keeps the sequenced upload, kernel-last ordering, post-publication
verification and sanitized diagnostics introduced for A5. Execution Semantics
is not part of this release; its complete scope moves to `0.1.0a7`.

## PyPI state before release

- `agnara` exists with `0.1.0a2`, `0.1.0a3` and the partial `0.1.0a4` release.
- No `0.1.0a5` artifact exists.
- `agnara-a2a`, `agnara-cli`, `agnara-events`, `agnara-http`, `agnara-mcp` and
  `agnara-telemetry` do not yet exist publicly.

## Owner checklist before tagging

1. Read back or create the Trusted Publisher for each canonical project name:
   provider `github`, owner `Blandskron`, repository `agnara`, workflow
   `release.yml`, environment `pypi`.
2. Record the explicit human confirmation for target `0.1.0a6` in
   `publication.json`; never record credentials or tokens.
3. Choose the `pypi` GitHub Environment protection policy.
4. Re-run publication readiness offline and online. Both must pass before
   creating `v0.1.0a6`.
